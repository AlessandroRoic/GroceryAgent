# Domain docs

This repository uses a single-context layout:

- GLOSSARY.md at the repository root defines domain vocabulary.
- docs/adr/ contains architecture decision records.

## Before exploring

Read GLOSSARY.md and any ADRs relevant to the area being explored.
If these files do not exist, proceed silently. Create domain documents
lazily through domain-modeling when terms or decisions are resolved.

## Vocabulary

Use glossary terms in issue titles, proposals, hypotheses, and tests.
If a needed concept is missing, reconsider the term or note the gap
for domain-modeling.

## Decision conflicts

Explicitly identify any proposal that contradicts an existing ADR.
Name the ADR and explain why the decision should be reopened.
